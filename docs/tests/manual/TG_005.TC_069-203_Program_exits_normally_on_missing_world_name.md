# Check issue no. #203's solution that the rendering module exits normally on missing world path parameter

## Tags
#pullRequest_203 #component_rendering #category_output 

_Related issue:_ https://github.com/codemetropolis/CodeMetropolis/issues/203
_Related branch:_ https://github.com/codemetropolis/CodeMetropolis/tree/203-rendering-with-empty-world-parameter-is-not-handled-correctly

### Purpose
 The purpose of this test is to see if the solution committed to issue no. #203 will perform its intended purpose (as stated in the issue's description) and the rendering module exits normally when world path parameter is not give to -w switch.

### Pre-requisites
- Java runtime 22
- Command line opened in the folder of rendering-1.5.0.jar
- A *placingToRendering.xml* file exists in the rendering-1.5.0.jar's folder. (Has to be a valid file, which was produced by running placing-1.5.0.jar with the *mappingToPlacing.xml* as input, which was generated by mapping-1.5.0.jar with the *cdfFile* generated by converter-1.5.0.jar with codemetropolis-toolchain-commons.graph as input)

### Steps
1. Run 
   ```cmd
   java -jar rendering-1.5.0.jar -i placingToRendering.xml -w
   ```
 in rendering-1.5.0.jar command line

### Expected Result
No behaviour occured while running the rendering module with missing world path parameter other than the program exiting normally.
