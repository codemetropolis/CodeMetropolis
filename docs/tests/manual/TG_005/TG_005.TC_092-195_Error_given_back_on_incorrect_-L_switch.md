# Check issue no. #195's solution if it gives back an error on capitalized -L or -LAYOUT switch

## Tags
#pullRequest_195 #component_placing #category_input

_Related issue:_ https://github.com/codemetropolis/CodeMetropolis/issues/195
_Related branch:_ https://github.com/codemetropolis/CodeMetropolis/tree/195-placing-with-empty-layout-parameter-is-not-handled-correctly

### Purpose
The purpose of this test is to see if the solution committed to the above issue gives back an error when trying to use layout parameter as *-L* or *-LAYOUT*.

### Pre-requisites
- Java runtime 1.8
- Command line opened in the folder of placing-1.4.0.jar
- A *mappingToPlacing.xml* file exists in the placing-1.4.0.jar's folder. (Has to be a valid file, which was produced by running converter-1.4.0.jar with the *converterToMapping.xml* as input)
  
### Steps
1. Run 
   ```cmd
   java -jar placing-1.4.0.jar -i mappingToPlacing.xml -L pack
   ```
   or 
	```cmd
	java -jar placing-1.4.0.jar -i mappingToPlacing.xml -LAYOUT pack
	```
in placing-1.4.0.jar command line

### Expected Result
The tool gives back a warning or error and the program will not finnish running because the capitalized -W or -WORLD switch does not equal to the default -w or -world switch.
