# [Test] Issue no. #199's solution only writes warning in to the console and no output file is created for it

_Related issue:_ https://github.com/codemetropolis/CodeMetropolis/issues/199
_Related branch:_ https://github.com/codemetropolis/CodeMetropolis/tree/199-rendering-with-invalid-inputfile-is-not-handled-correctly

**Purpose**: The purpose of this test is to see if the solution committed to issue no. #199 only writes the warning message (when rendering module is ran with a valid input file) in the console and no output file is created for this message.

**Pre-requisites**:		
- Java runtime 1.8
- Command line opened in the folder of rendering-1.4.0.jar
- A *placingToRendering.xml* file exists in the rendering-1.4.0.jar's folder. (Has to be a valid file, which was produced by running placing-1.4.0.jar with the *mappingToPlacing.xml* as input, which was generated by mapping-1.4.0.jar with the *cdfFile* generated by converter-1.4.0.jar with codemetropolis-toolchain-commons.graph as input)

**Steps**:
1. Open placingToRendering.xml in any kind of text editor
2. Delete its content from line 10 to 20 and save the file
3. Run `java -jar rendering-1.4.0.jar -i placingToRendering.xml -w world` in rendering-1.4.0.jar command line

_Expected result:_
The warning for the invalid input file only appears in console and no output file is created for it.
