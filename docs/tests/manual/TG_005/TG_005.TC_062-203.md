# [Test] Check issue no. #203's solution for capitalized -W or -WORLD switch reactions

_Related issue:_ https://github.com/codemetropolis/CodeMetropolis/issues/203
_Related branch:_ https://github.com/codemetropolis/CodeMetropolis/tree/203-rendering-with-empty-world-parameter-is-not-handled-correctly

**Purpose**: The purpose of this test is to check how the issue's solution reacts to capitalized switch cases.

**Pre-requisites**:		
- Java runtime 1.8
- Command line opened in the folder of rendering-1.4.0.jar
- A *placingToRendering.xml* file exists in the rendering-1.4.0.jar's folder. (Has to be a valid file, which was produced by running placing-1.4.0.jar with the *mappingToPlacing.xml* as input, which was generated by mapping-1.4.0.jar with the *cdfFile* generated by converter-1.4.0.jar with codemetropolis-toolchain-commons.graph as input)

**Steps**:
1. Run `java -jar rendering-1.4.0.jar -i placingToRendering.xml -W CodeMetroWorld` or `java -jar rendering-1.4.0.jar -i placingToRendering.xml -WORLD CodeMetroWorld` in rendering-1.4.0.jar command line

_Expected result:_
The tool gives back a warning or error and the program will not finnish running because the capitalized -W or -WORLD switch does not equal to the default -w or -world switch.

_Test result:_
`Incorrect command line arguments.`
`Usage: java -jar rendering-1.4.0.jar -i <inputFile> -world <worldPath>`
